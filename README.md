## 🎯 프로젝트 배경 및 목표

### 1. 응급실 핑퐁(재이송) 문제의 심각성
* 야간 및 공휴일 등 의료 취약 시간대에 응급 환자가 발생했을 때, 병원의 수용 거부나 전문의 부재로 인해 구급차가 여러 병원을 전전하다 골든타임을 놓치는 **'응급실 핑퐁(재이송)'** 현상이 사회적 재난으로 대두되고 있습니다.
* 환자 보호자는 다급한 상황에서 어느 병원에 가야 즉시 처치를 받을 수 있는지 알지 못해 단순 포털 검색이나 119 문의에만 의존하게 됩니다.

### 2. 핵심 목표: "단순 거리순이 아닌 실시간 수용 가능성 기반 최적 추천"
* 본 과제는 국립중앙의료원(NEMC) 공공데이터포털 실시간 OpenAPI와 웹 지도 API를 연동하여, **[실시간 이동시간 + 현재 잔여 병상 수 + 증상별 처치 가능 여부 + 현장 긴급 공지]**를 종합 연산하는 **위치 기반 실시간 응급의료 최적 추천 서비스**를 구축합니다.
* AI 생성 코드의 오류를 극복하고 원시 데이터의 무결성을 확보하여, 응급환자와 의료진 모두에게 가장 신뢰할 수 있는 정보를 제공합니다.

### [난제 1] 망 분리 및 캐싱 구조로 인한 동기화 시차 (Time-Lag)
* **현상**: 병원 현장 상황이 E-Gen 내부망에 등록된 후, 공공데이터포털 OpenAPI로 미러링되기까지 최대 약 30분의 동기화 시차 발생 (예: 강남세브란스병원 혈액투석 HD 항목 등).
* **한계**: 공공데이터 연계 서버의 배치 주기 및 망 분리 보안 정책으로 인해 클라이언트에서 선제 갱신 불가.
* **해결책**:
  1. 서비스 상단 및 카드에 **데이터 수신 타임스탬프(`hh:mm:ss KST`)를 명확히 표출**하여 정보 최신성을 투명하게 공개.
  2. 공공데이터의 구조적 시차 한계를 명시한 **이용 안내 및 면책 조항 팝업**을 상시 제공.
  3. 시차가 의심될 경우 사용자가 즉시 유선으로 확인할 수 있도록 **원클릭 응급실 직통전화(`tel:`) 연결 액션**을 전면에 배치.

### [난제 2] AI 코드 생성 도구의 맹점과 수동 검증
* **현상**:
  1. 외부 AI 환경에서 공공데이터 서버 통신 시 HTTP 403 차단이 발생하여 실제 응답값을 검증하지 못한 채 그럴듯한 환각(Hallucination) 코드 생성.
  2. 직관성이 떨어지는 API 필드명(`hvec`, `hvs01`, `mkioskty1` 등)으로 인해 기준 병상수를 질환 번호로 오인하는 등 분류 오류 발생.
* **해결책**:
  1. 로컬 환경에서 직접 패킷을 캡처하고 공식 데이터 명세서를 1:1 대조 분석.
  2. `app.js` 내에 **`HV_LABELS`**, **`HVS_LABELS`**, **`API_FIELD_LABELS`** 등의 정규 매핑 테이블을 수동 선언하여 오해석 차단.
  3. 무가공 원본 데이터를 실시간 검사할 수 있는 **'개발자 모드(Developer Mode Raw Inspector)'**를 구현하여 투명한 검증 파이프라인 수립.

```javascript
// app.js에 개발자가 직접 명세를 대조하여 구축한 수동 매핑 테이블
const HV_LABELS = {
    hvec: '응급실 일반 병상',
    hv28: '소아 응급 병상',
    hv29: '음압격리 병상',
    hv30: '일반격리 병상',
    hv15: '소아 음압격리 병상',
    hv16: '소아 일반격리 병상',
    hv27: '코호트 격리 병상'
};
```

### [난제 3] 결측값(Null) 처리 및 집계 기준의 복잡성
* **현상**:
  1. XML 응답 태그가 비어있는 결측값을 단순 `0`으로 치환할 경우, **"정보 없음"이 "병상 없음(만실)"으로 왜곡 표출**되어 환자가 진료 가능한 병원을 기피하는 심각한 의료 사고 유발.
  2. 공공데이터 API에서 병상 수가 음수(`-2` 등)로 반환되는 비정상 데이터 발생.
  3. 웹 E-Gen 화면과 OpenAPI 간 병상 집계 범위(원내 입원 격리 vs 응급실 내부 격리) 불일치.
* **해결책**:
  1. **엄격한 결측치 분리**: `isBlankOrNull()` 헬퍼를 도입하여 결측값은 수치 0과 분리하고 정직하게 `[-]` 대시로 표기.
  2. **음수값의 도메인 분석**: 음수값은 결측이 아닌 **'기준 정원을 초과하여 수용한 병상 수'**임을 밝혀내고 `초과수용 N석` 빨간색 배지로 정확히 렌더링.
  3. **긴급 공지 교차 검증 엔진 (`isDiseaseSpecificallyBlocked`)**: API 상으로 '가능'이어도 활성 공지에서 해당 진료과/질환의 차단 키워드가 감지되면 `[불가능]`으로 자동 전환.

```javascript
// 결측치(공란)와 음수 초과수용을 엄격히 구분하는 핵심 로직
if (isBlankOrNull(rawVal)) {
    return { className: 'egen-badge-dash', text: '-' }; // 알 수 없음
}
if (current < 0) {
    const overflow = Math.abs(current);
    return { className: 'egen-badge-pill-red', text: `초과수용 ${overflow}` }; // 정원 초과
}
```

* 최소 터치 타깃 **44px 이상** 확보 및 터치 시 햅틱 감각의 `:active` 축소 애니메이션.
* 최신 스마트폰 노치(Notch) 및 홈 바 보호를 위한 `viewport-fit=cover` 및 Safe Area Inset 패딩 적용.
* 지도 조작(드래그/줌) 시 스마트폰 가상 키보드가 화면을 가리지 않도록 검색창 포커스 자동 해제(`blurKeyword`).

### 4. 웹 접근성(A11y) 표준 준수
* 모달 및 바텀시트 활성화 시 백그라운드 요소에 `inert` 속성을 부여하여 초점 분산 방지.
* `Escape` 키를 통한 계층적 레이어 닫기 및 시트 내부 `Tab` 키 포커스 트랩(Focus Trap) 완비.

## 💻 실행 및 로컬 테스트 방법

별도의 빌드 도구나 Node.js 패키지 설치 없이 브라우저 환경에서 즉시 실행 가능한 순수 웹 표준(Vanilla Web) 프로젝트입니다.

### 방법 1: VS Code / WebStorm Live Server
1. WebStorm 또는 VS Code에서 본 프로젝트 폴더를 엽니다.
2. `index.html`을 우클릭한 후 **'Open with Live Server'**를 선택하여 실행합니다.

### 방법 2: Python 내장 로컬 웹 서버
```bash
# 프로젝트 루트 폴더에서 터미널 실행
python -m http.server 8000

# 브라우저에서 접속
http://localhost:8000
```

> **주의 사항**:  
> 카카오 지도 SDK는 로컬 서버(`http://localhost` 또는 `http://127.0.0.1`) 환경에서 정상 구동되도록 도메인 등록이 완료되어 있습니다. 반드시 로컬 웹 서버를 통해 실행해 주시기 바랍니다.
